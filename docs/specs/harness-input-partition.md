# Phase119 input partition v1 — implementation contract draft

1 November 2026. Parent adopted exhaustive explicit classification, no filename/default-public inference, a public-view-only projection and independent private reconstruction. This document specifies that bounded component; it does not approve live dispatch. No new scheduler, storage root, CLI, provider operation or spend API. Existing offline schemas, composition, export bytes and retained report algorithms remain unchanged.

## 1. Types and bounds

All JSON objects below have exactly the listed keys; reject extras/missing fields. `Hash` is lowercase SHA-256; `Commit` and `Blob` are lowercase 40-character Git SHA-1 for this historical v1. `Ref<K> = {kind:K,id:EvaluationId,digest:Hash}`. `Path` satisfies existing `filePath`; `Mode` is `100644|100755`; byte lengths are nonnegative safe integers. Roles are exactly `public|evaluator-only`. Use existing `sealRecord`/`fingerprint` for record digests; raw-file identities use `byteDigest`. Neither hash is a signature or permission grant.

Reuse FILE_LIMIT=128, ARTIFACT_BYTES=262144, material limit=65536 and stdout envelope limit=393216. Bound each partition/manifest JSON to EVALUATION_BYTES before parsing/validation. This new JSON reader rejects malformed UTF-8, duplicate keys, lone surrogates, depth >16 and non-JSON data. No Unicode/path/line-ending normalization. These checks do not change legacy parsing.

## 2. Reviewed classification source

Add one installed source file, `lib/evaluation-corpus/input-classification-v1.json`, with this closed shape:

```text
{
  schemaVersion:1, kind:"evaluation-input-classification", revision:positiveInteger,
  catalogDigest:Hash,
  cases:[{
    case:Ref<"case">, startingCommit:Commit,
    sources:[{path:Path,mode:Mode,blob:Blob,byteDigest:Hash,bytes:Integer,role:Role}],
    evaluatorFiles:[{path:Path,material:Ref<"material">,byteDigest:Hash,bytes:Integer}],
    acceptance:{material:Ref<"material">,byteDigest:Hash,bytes:Integer},
    requirements:{role:"public",byteDigest:Hash,bytes:Integer}
  }],
  publicMaterials:[{path:Path,material:Ref<"material">,byteDigest:Hash,bytes:Integer}]
}
```

Cases sorted by case ID, sources/evaluatorFiles by path, publicMaterials by `(path,material.id,material.digest)` using code-point ordering. No duplicate keys/entries. At most 20 cases, 128 sources and 128 evaluatorFiles per case, 200 publicMaterials. Bind `catalogDigest` to exact installed catalog bytes. Every case ref must match the installed corpus definition and starting revision exactly. Source rows must equal its entire pinned source inventory, adding explicit modes and roles. Evaluator rows name the complete reviewed probe/support closure, with exact **delivered/transformed** material identities, not raw provenance-header bytes. Acceptance must equal that case's acceptanceManifest. Requirements hash the exact controller-generated bytes described below.

Initial reviewed cases: `package-entry` and `workspace-command-doc`; all their enumerated historical source rows explicitly public; all probe/support rows evaluator-only; acceptance evaluator-only. Do not copy acceptance values, probe bodies or corrected witness source into this manifest. Populate identities through trusted local curation; checking identities is not permission to publish them. Other cases refuse until explicitly reviewed. Public candidate/context materials require exact entries in `publicMaterials`; start with an empty list if none have been reviewed. Never whitelist arbitrary config materials by their presence in context/overlays.

Manifest bytes plus revision are versioned/reviewed source. `classificationDigest = byteDigest(raw manifest bytes)`; any change invalidates new preparations. No descriptor-supplied manifest path, role override or automatic refresh. Production loader returns an opaque frozen ReviewedClassification handle (private WeakMap); plain caller JSON is not a reviewed handle. Synthetic installed-app fixtures may replace this source in isolated test copies; no production test bypass. Review provenance is repository source review, not an invented runtime `approved:true` flag.

## 3. Exact partition record

A successful preparation emits this immutable **local/private** value (not automatically written anywhere):

```text
{
  schemaVersion:1, kind:"evaluation-input-partition",
  planDigest:Hash, case:Ref<"case">, configuration:Ref<"configuration">,
  startingCommit:Commit,
  environment:{image,platform,dependencyLock,installer},
  classificationDigest:Hash,
  entries:[SourceEntry|MaterialEntry|AcceptanceEntry|RequirementsEntry],
  digest:Hash
}
SourceEntry = {
  kind:"source",role:Role,path:Path,mode:Mode,blob:Blob,byteDigest:Hash,bytes:Integer
}
MaterialEntry = {
  kind:"context"|"overlay",role:Role,index:Integer,path:Path,mode:"100644",
  material:Ref<"material">,byteDigest:Hash,bytes:Integer
}
AcceptanceEntry = {
  kind:"acceptance",role:"evaluator-only",
  material:Ref<"material">,byteDigest:Hash,bytes:Integer
}
RequirementsEntry = {
  kind:"requirements",role:"public",path:"requirements.json",mode:"100644",
  byteDigest:Hash,bytes:Integer
}
```

`index` is the zero-based index within the exact configuration array. Order entries: source rows sorted by path; context in original index order; overlays in original index order; one acceptance; one requirements. Never sort/reorder context and overlays. No timestamps or random IDs. `digest = sealRecord(record).digest`.

Require a validated frozen schema-3 plan and exact comparison-referenced case/configuration; use `resolveCaseEnvironment`. Verify exported source bytes, modes and Git blob hashes against the reviewed source inventory. Selected sourcePaths must equal that inventory, with no subsets/extra files. Every context/overlay occurrence must match either a reviewed publicMaterials row (public) or this case's evaluatorFiles row (evaluator-only), never both. Every evaluatorFiles row must appear exactly once. Unreferenced bundle materials are not inputs and are never traversed for projection. Acceptance is resolved only for the selected exact case. Require the case's public brief/requirements and all referenced sealed records to remain digest-valid.

Small v1 restriction: nonempty configuration exclusions refuse in this new branch (`partition_unsupported`). Existing offline exclusions still work unchanged. No implicit dropping or replacement to make a recipe fit.

Requirements bytes are UTF-8 `JSON.stringify({publicBrief:task.publicBrief,requirements:task.requirements})` in that property order; compare to the reviewed requirements identity. Material file bytes are exact UTF-8 material content, validated before encoding. Source text/binary publicity is determined only by explicit review; a later text packet renderer must separately refuse unsupported encodings.

## 4. Closed public view and preparation identity

```text
File = {path:Path,mode:Mode,base64:canonicalBase64}
PublicView = {
  schemaVersion:1, kind:"evaluation-public-input",
  publicBrief:String, requirements:[String],
  files:[File], writablePaths:[Path]
}
PreparationIdentity = {
  schemaVersion:1, kind:"evaluation-input-preparation",
  planDigest:Hash, partitionDigest:Hash, classificationDigest:Hash,
  builderFilesDigest:Hash, evaluatorFilesDigest:Hash,
  acceptanceDigest:Hash, publicViewDigest:Hash,
  digest:Hash
}
```

Public files contain only explicitly public sources/context/overlays, in partition occurrence order; requirements are represented by the two explicit public fields, not duplicated in `files`. Builder files additionally contain generated requirements.json. Evaluator files here mean **only the evaluator-only file dependencies**, not the public files or the acceptance manifest. Each files digest fingerprints its existing `validateFiles` sorted output. PublicViewDigest fingerprints the closed public view. Writable paths are the exact task allowlist, sorted, and must refer to existing public source files only in this v1; read-only public materials and requirements cannot be writable. No new-file creation, deletions or mode widening in this slice.

No case/config/plan/partition/classification/evaluator digests, private filenames, driver/check IDs, argv, expected output, stdin, provenance, host paths or metadata are fields of PublicView. These remain local/private binding data. A future approved packet adds its own fixed template/result schema around this view; this slice does not implement or duplicate provider packet hashing.

Deep-copy validated inputs and deep-freeze returned views/records. Keep private bytes, driver and the original source snapshot in a private WeakMap keyed by an opaque PreparedPartition handle. A plain/deserialized record or public view cannot reconstruct private input or establish trust. Preparation identity is stable across repeated identical reads. Changing any source/config/role/private dependency changes or invalidates it. There is no durable write: a later live intent must bind this exact identity and rederive it against the then-current trusted source before any count/generation approval can be used.

## 5. APIs and collision rules

Proposed exports; all errors follow section 6:

```text
// evaluation-corpus.mjs: local bounded reads only, no export writes
loadReviewedInputClassification() -> Promise<ReviewedClassification>
prepareCorpusInputPartition({plan,caseRef,configurationRef,repository,sourcePaths})
  -> Promise<PreparedPartition>

// new evaluation-input-partition.mjs: pure, no I/O or callbacks
prepareInputPartition({plan,caseRef,configurationRef,sourceFiles,reviewed})
  -> PreparedPartition
partitionIdentity(prepared) -> deep-frozen PreparationIdentity
partitionRecord(prepared) -> deep-frozen private PartitionRecord
publicInputView(prepared) -> branded, deep-frozen PublicView
projectPublicInput(publicView) -> fresh plain PublicView
reconstructEvaluatorInput(prepared,submissionStdout)
  -> {files:[File],driver:validatedStdioDriver}
```

The wrapper loads the installed reviewed handle, exports exact Git source via existing exportSource and calls the pure preparer. The pure preparer verifies source hashes itself, rather than trusting the wrapper. Reuse acceptanceDriver solely inside the private preparation/reconstruction path. Public projection accepts only branded PublicView, verifies its private registered digest and constructs the exact public schema; it never accepts the bundle, preparation handle, evaluator object or arbitrary deserialized JSON. Brand checks prevent accidental cross-boundary calls; they are not protection from arbitrary trusted host code.

Reject duplicate paths **before** constructing any Map, across sources, context, overlays, generated requirements and evaluator files, even if bytes match. Reject file/directory prefix collisions across the full union and aliases disallowed by filePath. Reject duplicate material assignment to competing roles. Check argv script dependencies are members of the reviewed evaluator-only set; no public check script. Unknown dynamic dependencies refuse via missing reviewed closure, not speculative static import scanning.

Historical exception is about bytes, not paths: control evaluator support can contain the same bytes as the public README at a distinct explicitly reviewed path. Equal bytes do not grant public status; this is not a role override. Preserve the existing additional guard against public copies of the selected acceptance-manifest material. Explicit review, not substring heuristics, is responsible for not misclassifying embedded secrets.

Reconstruction first validates the existing base64 stdout envelope against original **public builder files**, exact writable paths and all public read-only/protected paths using submittedArtifact. Require replacement paths already exist and modes equal originals. Then add exact private dependency bytes from the prepared snapshot, recheck disjoint paths/full-union FILE_LIMIT and ARTIFACT_BYTES, and return the unchanged privately validated driver separately. Private dependencies never originate in model output. Provider completion, reconstruction or driver return is not acceptance. No host writes, execution or model-selected checks.

Preparation validates builder files, evaluator dependencies and their combined initial union under existing bounds; reconstruction repeats union checks after edits. Reject any partial result on failure. Existing composeExecutionDelivery remains the legacy implementation; do not route old execution/screening records through this new classifier.

## 6. Error boundary

Export only fixed codes/messages with exitCode 2: `partition_invalid`, `partition_unsupported`, `partition_unreviewed`, `partition_binding_mismatch`, `partition_incomplete`, `partition_collision`, `partition_bounds`, `partition_submission_invalid`. Do not attach cause, raw exceptions, paths, material IDs, refs/digests, contents or private field names. Catch filesystem/Git/parser/artifact validation errors at exported boundaries and map them to these codes. No logging or stdout diagnostics in these APIs. The private partition/identity APIs are explicitly not public diagnostics. No credentials are accepted/read by any API.

## 7. Executable acceptance and regression boundaries (planned, not run)

New `tests/evaluation-input-partition.test.mjs`, plus focused extensions to existing corpus/isolation tests:

- Exact synthetic target/control preparations produce stable record/identity and independent reconstruction. Installed historical metadata/source-only checks cover the two reviewed inventories; no answer text enters public fixtures or logs.
- Synthetic distinct canaries in every evaluator file/path/ID, manifest field, check argv/stdin/expected output and provenance are absent from JSON(projectPublicInput(view)) and every exported error. Public read-only lesson text and public requirements remain present.
- Missing/extra/duplicate/reordered classification, wrong source blob/hash/mode, case/config/material refs, changed reviewed bytes, stale preparation, arbitrary unbranded input, ambiguous roles and unsupported exclusions refuse. Deep mutation cannot alter a prepared snapshot. Both arms use exact per-case environment bindings.
- Source/context/overlay collisions, requirements shadowing, path-prefix collisions, evaluator path in writable paths, renamed or changed private material relabeled without reviewed metadata and altered output modes refuse before reconstruction.
- Same bytes at explicitly distinct public/evaluator paths work for the control shape; equality alone never classifies content. Empty replacement list preserves originals. Private dependency modification/omission in output cannot affect reconstructed evaluator bytes/driver.
- Boundaries at 128 files, 256KiB combined bytes, 384KiB envelope; edited public bytes that overflow the combined evaluator union refuse. Invalid UTF-8/JSON/duplicate keys/lone surrogates refuse without leaking nested data.
- Existing offline composition, source/export bytes, schema-2/3 freeze receipts, V1/V2 reports and offline exclusions retain current behavior. No new CLI branch or provider call is reachable.
- Causal controls: leak evaluator files into public projection; remove exact binding/role coverage; permit cross-role collision; reconstruct without private dependencies. Each must fail its named assertion. Parent owns later integrated validation/source pins; no tests while current checkpoint runs.

Implementation files: new pure partition module and reviewed manifest; narrow additive entry points in evaluation-corpus.mjs. Reuse evaluation-records.mjs, evaluation-artifacts.mjs and evaluation-execution-input.mjs primitives without changing legacy outputs. No execution/ledger/spend/provider/CLI/report migration in this slice. Future source-pin coverage must include new modules only once a real supported preparation consumer executes them.
