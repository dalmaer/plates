# Proven rollout practice reaches the fleet

## Done when

A reviewed reusable practice helps representative projects integrate small increments and expose them deliberately, with observed speed and stability and honest coverage gaps.

## Scope

Turn the pilot's demonstrated contracts into an optional reusable practice,
project-specific guidance and compatible adoption proposals. Reuse existing
reviewed release, rehearsal and fleet-update paths (phases 48, 53, 105 and 131).
Non-goals: mandatory centralized flag service, automatic fleet migration, new
scheduler/authority, or copying pilot thresholds to unrelated workloads.

Read [the Plates philosophy](../philosophy.md); preserve existing phase ownership
and evidence. Dependencies name prerequisites, not automatic acceptance of their
outstanding real-surface walks.

## Integration increments

1. First safe merge: distill pilot evidence into the smallest template/check
   contract; document what remains component-specific and preserve opt-out.
2. Ship reviewed managed sources with compatible updates and adoption previews.
3. Adopt on a small authorized representative set, compare dated speed/stability
   measures, and only then propose broader installation. Keep consumer-owned work.
4. Retire pilot flags/compatibility paths only when each removal condition is
   proven; preserve historical receipts. Recovery uses the existing reviewed
   update/revert mechanism and component-specific effect limits.

## Proof

Use the existing reviewed practice-release and consumer-rehearsal paths; pin
candidate sources and actual consumer configurations. Run
`npm run check:focused -- tests/adopt.test.mjs tests/plates-generated.test.mjs`,
`npm run render:check`, `npm run check` and `npm run typecheck`. Record real adopted
source/managed bytes and follow-up windows separately from source tests. Broad
publication and installation require their existing authority; local preparation
does not imply the fleet has adopted the practice.

## Real surfaces

- adopted project: verify selected real consumer update and its preserved local files.
- fleet over time: compare baseline and follow-up speed/stability with sufficient meaningful operations and explicit incomplete coverage.

## Deliberately open

The pilot may show that documentation plus existing delivery tools is enough;
do not manufacture a runtime abstraction. Consumer selection, rollout allowance
and observation windows are decided from phase 160 evidence. Generalization is
not a claim of universal applicability or statistically established improvement.
